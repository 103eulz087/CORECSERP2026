## Bugs Encountered (known patterns)

- **Reset Entry not called after save (Known Bug Pattern #6)** — `ClientPaymentsDevExAcctg.ProcessPayment()` disposed the control instead of resetting it. Only surfaced once the screen was actually wired into a persistent host today.
- **Payment-touched-a-posting → reversal, not edit (Known Bug Pattern #4)** — applied directly: Edit Details reverses via `sp_ReversePaymentClient` rather than editing in place.
- **TOP-1-without-deterministic-tiebreak** — a new variant worth remembering: a `LEFT JOIN` + `TOP 1` silently depended on an unenforced data convention (every `ARPaymentDetails` row for a header carries the same GL code) instead of being structurally guaranteed. `OUTER APPLY` per sub-source is the safer shape.
- **DBNull vs `?? 0`** — `?? 0` does not catch `DBNull.Value` (it's not a null reference); `Convert.ToDouble(DBNull.Value)` throws. Caught in the pre-fill loop before it shipped.
