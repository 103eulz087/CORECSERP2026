## 2. What changes for users (by menu)

### Starting the program (everyone)
- A small "Starting CORE-X ERP..." window shows from the first second until the Login appears. After an update it says
  "Finishing the update...". It shows what it is doing: connecting to the database, loading config, checking for
  updates, opening login.
- The Login now comes to the front by itself. After an update it used to open behind other windows, so the restart
  looked stuck.

### Accounting Board › GL Detail Transaction (new; anyone allowed a posting page on the board, or granted it in User Access)
- New item on the board. It is the same report as Accounting Reports › GL Detail Transaction, so staff can check what
  they just posted without leaving the board. Right-click a line to see the whole ticket.
- In the "View Related Entries (Same Ticket)" popup (here and in Accounting Reports), Debit / Credit now show as amounts
  (1,234,567.89), right-aligned, with totals at the bottom.

### Accounting Board › Post Expense › Single Mode (accounting)
- New **Reverse…** button (also on the right-click menu) on the Posted tab, for an expense that should never have been
  keyed. Enter a reason (required, up to 300 characters). The reversal is dated like the expense. The expense stays on the
  list as **CANCELLED** (grey, struck through) with who / when / why. It can't be edited or reversed again; use Copy to
  New Entry to post the right one.
- The invoice no. of a cancelled expense can be posted again.
- Messages you may see:
  - "already has a payment, withholding or offset": reverse the payment voucher first (Supplier Voucher Reversal).
  - The shipment's stock was already sold, transferred, converted or adjusted: the expense can't be reversed, because
    that stock already carries the cost.
  - The expense was posted before 2026-09-25 09:48: it can't be reversed here.
  - The expense's month is closed in the GL: ask an admin to reopen the month.

### Accounting Board › Manual Ticket (multi-branch Manual JV) (accounting)
- New **Reverse Voucher…** button with a reason. One reversal is posted for every branch, dated like the voucher, and
  its bank recon items are voided. The voucher stays listed as CANCELLED and can't be edited.
  - It is refused if a bank item of the voucher was already cleared, or if its recon month (or a later one) is locked.
- **Save Changes with nothing changed** now says "No Changes" and posts nothing. The ticket no. stays the same and the
  original preparer is kept.
- The Posted list shows Prepared By / Date Prepared (the first poster) and Last Modified By / Last Modified Date (the last
  real edit). Edits made before 2026-10-14 had overwritten the preparer, so for those vouchers the list shows the last
  editor as the preparer.

### Accounting Board › Vouchering › Posting Cash/Check (Supplier Payment) (accounting)
- **Purchases and expenses are in one list.** The Purchase / Expense buttons are gone, and a **Kind** column shows each
  invoice's type. One cash or cheque voucher may pay both kinds together: one cheque, one voucher.
- The footer totals add up the **ticked** rows only.
- On a telegraphic voucher you can still pay only one kind at a time. A message explains this if both kinds are ticked.
- The supplier list shows **local** suppliers, plus import suppliers marked "Pay by Cash/Check AND Telegraphic". On
  PRODUCTION that is 141 suppliers; JANIVA (000121) is the one marked for both.
- The supplier pick now uses the supplier's code, so suppliers with the same name no longer get mixed up, and you can't
  type a name that isn't on the list.
- Right-click › Show Invoice Details works on expense rows. On a purchase row it now says so.

### Accounting Board › Vouchering › Posting Telegraphic (accounting)
- The supplier list shows **import** suppliers only (10 on PRODUCTION: 000121–000129 and 000132), plus any supplier
  marked for both.
- New red **Amount:** figure in the header: the total to apply of the ticked invoices.
- (Server side, already live) A telegraphic voucher with GL lines only and no invoice (e.g. a PROFOOD loan / advance
  payment) can now be reversed from Payment List. It used to fail with "Nothing found to reverse".

### ADMIN TOOLS › GENERAL ADMINISTRATION › Suppliers info
- New tick box **"Pay by Cash/Check AND Telegraphic"**. Tick it for a supplier paid both ways, so it shows on both
  payment screens.
- Update now saves safely: an apostrophe in a name no longer breaks it, and if the save fails, what you typed stays on
  screen.

### ADMIN TOOLS › GENERAL ADMINISTRATION › Account Officers (new; admins, whoever sees Customers Info, or granted `btnAccountOfficers`)
- New screen to add, rename and delete the account officers in the customer screens' dropdown. It also shows how many
  customers each officer has (e.g. Leah Banibane 2,961 on PRODUCTION).
- **Renaming an officer renames them on all their customers.** The screen asks first and shows the number of customers.
- An officer who still has customers can't be deleted, and two officers can't have the same name.

### ADMIN TOOLS › SALES ADMINISTRATION › Products
- **Add puts the new product in every branch.** Since the copy step was switched off, new products had stayed in head
  office only, e.g. 16036 PORK DRIPLOSS on PRODUCTION (since fixed by [94]). The message says how many branches.
- Category, prices and re-order level are checked before saving. "Product Code Already Exist" if the code is taken.

### SALES › SALES ORDER › View Sales Order
- Delivered and Paid tabs: Total Items / Sold / Qty now count the delivery lines, without cancelled lines. Example: PO
  12415 showed 3 items / 1 sold, and now shows 2 / 2.
- Paid tab: right-click now has **Show Items** and **Show Returned Items** (for a PO with a return). A fully returned
  PO that was paid now also shows on the Paid tab.

### REPORTING › SALES › Registers (Invoice / CR / EWT) (new; admins, accounting, whoever sees Client Sales, or granted `btnRegisters`)
- New window with three tabs: **Invoice Register**, **Collection Receipt Register** and **EWT Payable**.
  - The EWT tab is for admins / accounting only.
- Pick the branch and dates, then press Generate. Export to Excel is available.
- The registers flag DUPLICATE numbers and GAPs in each series. EWT Payable shows each amount withheld as PAID / PARTIAL
  / UNPAID: remittances pay the oldest first. Example: the 956,909.86 opening is PAID.
- Drag a column header to the top to group by it. Each group then shows its subtotals.

### REPORTING › SALES › Client Sales (POS Sales Report) › Sales Journal
- New column **Reference Code**: the inventory lot each sale was taken from.

### REPORTING › INVENTORY REPORTS › Item Costing Report
- The movement ledger under each item now has proper captions (Qty In, Amount Out, Running Value...).
- Its quantities (3 decimals) and amounts (2 decimals) are right-aligned.
- Sales Amount is hidden there.

### INVENTORY › INVENTORY PROCESS › Inventory Qty Adjustment; ACCOUNTING › Add Purchase Order; View Expense › Edit; POS charge / payment / cash wallet
- The customer / supplier / product pick now uses the record's code, not its name. 988 customers share a name on
  PRODUCTION, and before this the second one of a pair could never be picked.
- You can no longer type a name that isn't on the list. Nothing else changes on these screens.

### ADMIN TOOLS › GENERAL ADMINISTRATION › User Access
- New entry "GL Detail Transaction" for the Accounting Board, to give the report to someone with no posting page.

### Already live on the database (any exe; installed 10-14 / 10-15)
- Client payment: refused if an invoice isn't the customer's, or was paid by someone else meanwhile (92015–92017).
  Reload the invoices and post again.
- Bank recon: items of a locked month can't be added, changed or deleted.
  - Only hand-typed / balance-forward items can be deleted; other items are taken back by reversing their document.
  - Auto-Match is switched off.
  - A posting whose bank item doesn't match an existing one is refused (93021) instead of silently dropped.
